# Working on Norvak Web V3

This is a personal portfolio maintained by José Cortés. Keep changes focused on the project brief and current roadmap.

## Workflow

1. Start from the latest `main` branch.
2. Use a descriptive branch for a meaningful change, such as `feature/work-page` or `fix/mobile-navigation`.
3. Keep commits small and describe the resulting change clearly.
4. Open a pull request for changes that benefit from review. Summarize the change and the checks completed.

For simple solo work, a clear commit on `main` is also acceptable. Do not add process that obscures the actual change.

## Code and content

- Use the repository’s indentation and formatting settings.
- Keep code readable and avoid unrelated formatting or dependency changes.
- Preserve both language versions when editing bilingual content.
- Do not publish secrets or personal information in issues, commits, or screenshots.
- Retain asset attribution and licenses.
- Describe actual capabilities and results accurately.

## Verification

Use checks appropriate to the change. For a UI change, review the affected page on desktop and mobile, test the relevant interaction with a keyboard, and check for broken navigation or assets. Include screenshots when useful. For documentation-only work, verify links and accuracy; no application test suite is required.
